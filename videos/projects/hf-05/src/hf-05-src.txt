哈喽大家好，我是叶扬。

上一集，我们终于让 div 动起来了：暂停的时间轴、seek 到任意一秒、帧帧可复现。可新问题来了——一个项目几百行 HTML、几十条动画，写完怎么知道自己没写错？靠眼睛从头看一遍？我先给你看个东西：有个错，就明晃晃写在标题的颜色值里，我自己盯着看了半天，没看出来。

今天的主角，是官方守门员：check。

先把丑话说前头，它不是万能的。上一集那个 setInterval 计数器，check 一路绿灯，可六个渲染器同时问第二秒，回来好几个不同的数——动画能不能被定位，这种运行时的逻辑，守门员不管。它管的是另一大类错：结构写错没、控制台炸没炸、布局遮没遮、字看不看得清。今天你会发现，光是这一类，就够救你好几回。

工程已经打开了，就一个标题、一个副标题，十秒。终端里敲：npx hyperframes@0.8.107 check，回车。注意，它不是一条检查，是六道关，一段段给你过。第一关 Lint，不起浏览器，纯读文件，查时间属性、查媒体文件在不在；第二关 Runtime，真开一个无头 Chrome 把页面跑起来，收控制台里的错和警告；第三关 Layout，在时间轴上抽九个点，一个个 seek 过去量布局；第四关 Motion，查动画写法——你要是写个无限循环，repeat 设成负一，它就黄你一下：视频是有终点的，末帧定格时循环停在哪，你想过没有；第五关 Contrast，每个采样点量文字和底色的对比度；最后一关 Snapshots，没配就是 disabled。全绿，Check passed。

好，开始给它喂错。第一个，把标题身上的 data-duration 删掉。存盘，再 check。

一行黄字，规则名 timeline_element_missing_timing：说这个元素是时间轴上的元素，却没有时长，时间轴画不出它在哪儿结束。可你抬头看——Check passed，绿灯。

这是今天第一个反直觉：这种错，它只警告，不拦你。为什么不拦？页面照样成立、照样能渲染；但后果是真的，它也写明了：预览、海报帧、最终渲染，这个元素都可能被切掉。所以黄字不是凑数的，是给人读的。

再来一个。片尾加个彩蛋，第八秒进来，待五秒。片子总长十秒，它得到第十三秒才走。check：clip_ends_past_root_duration，还是黄字。但这条警告有点东西，它直接递上两条修法：要么把根时长延到十三秒，要么让彩蛋在第十秒前结束。我选第一条，root 的 data-duration 改成十三，再跑——绿了。

两条黄字看明白，规律就出来了：页面还成立、但有后果的，是警告；页面不成立的，是错误。再看退出码——有错，退出码是一；纯警告或者全绿，是零。所以这道闸能直接挂进 CI：退出码零才放行，黄字留给人逐条读。记住这句话：绿灯，从来不是免死金牌。

下面这个错，是让我决定拍这集的原因。

标题颜色我想弄高级点，挑了个深蓝灰，井号 1a1f26。说实话，在编辑器里我没觉得有大问题。check——Contrast 这一段，四个检查点全红：一点一四比一，而大字的门槛，是三比一。Check failed，这一类是错误，退出码一，真拦。

为什么大字反而只要三比一，不是常见的四点五？这是无障碍标准 WCAG 的口径：字越大、笔画越粗，容忍度越高。可我们这个标题，连三比一的一半都没到。

最狠的是，它不光说你错了，还直接递上修好的颜色：试试 rgb(93,97,102)。抄上，复跑——十个检查点，十分之十，全过。

那问题来了：这种错，第一关 Lint 为什么抓不着？因为「这个字在画面上到底清不清楚」，读文本是算不出来的。颜色叠上底色、透明度、动画走到一半的中间态，都得 Chrome 真把像素画出来才知道。这就是六道关为什么分三层：静态读文件能查的，归 Lint；真跑起来才暴露的，归 Runtime；渲染出来才量得出的遮挡和对比，归 Layout 和 Contrast。人眼会累、会脑补，机器的采样点一个不落。

下一个实验，考的是成见。

两个片段，data-track-index 都写一，时间还重叠：标题跟副标题，在同一根轨上叠着。按剪视频软件的直觉，同轨撞车，该报错了吧？check——全绿。

因为在渲染器眼里，压根没有「轨」这个东西。track-index 只是给官方 Studio 画轨道用的元数据；真正决定谁盖谁的，是 DOM 顺序，跟上一集讲层叠是同一个道理。

光说不练不过瘾，我在编辑器里把两个 div 的前后顺序对调一下，别的什么都不动，check——照样全绿。顺序怎么排，是你的设计，它不评判；它只在排序的后果真的闯了祸时，才出手。

可你别以为它好糊弄。我再贴一个不透明的色块，压在标题上。这回不管你写的是第几轨，Layout 的九个采样点，从零点五六秒到九点四四秒，一个不落全抓到，最后聚成一条错误：text_occluded，文字藏在不透明元素底下。Check failed，退出码一。它查的从来是画面上的结果，不是你起的名字。

最后一种错，最阴。

给副标题补个淡入动画，选择器一顺手，井号 sub 拼成了井号 sut。镜头先给你看代码，就这一行。check——passed，绿灯。但 Runtime 段里躺着三行警告：一行点了名，GSAP target 井号 sut not found；还有两行，连目标名字都是空的。同一处拼错，时间轴刚起步记了两回，走到一点六六七秒，又记一回。副标题的动画，就这么静悄悄地没了：不报错，不崩，不提醒你第二遍。

所以记住这个画面：绿灯不代表没事，黄字得逐条读完。那要是写错的不是选择器，而是真调了个不存在的函数？控制台直接 page_error，红的，而且后面的关卡连坐——时间轴压根没跑起来，它会明说：这一趟所有的绿，都不可信。

check 之外，还有三个体检命令，快速过一遍。

keyframes，把全片动画一条条列出来：哪个文件、哪个元素、什么写法、从第几秒到第几秒。比如标题这条：index.html 里的井号 title，visual，fromTo，从零秒到一秒，零 percent 时透明度零，一百 percent 时透明度一，清清楚楚。加个 --shot 参数，它还真去渲染一张洋葱皮图，首帧尾帧叠在一块，动没动、动够没动，一眼破案。

inspect，还能跑，但终端第一句就劝退：这命令已经废弃，将来要删，请改用 check。底下它照样把布局查了一遍——九个采样点，零问题。说白了，它如今就是 check 里的一小块。

beats，是给音乐轨数拍子用的。这片没音乐，它直接一行红字：没找到音乐轨，给 audio 元素加个 data-timeline-role 等于 music，或者把 id 起成 music、bgm、soundtrack，它也认。注意，这行红是它没活干，不是片子判了错。

check 是出门前的安检，这三个，是体检报告。

收尾。看过了绿，也看过了红，最后亲手验证一下退出码：全绿之后，在 cmd 里另起一行，echo 百分号 ERRORLEVEL 百分号——屏幕上回显零。这就是 CI 能认的那个零。

check 把机器能判的都替你判了：结构、报错、遮挡、对比度；但片子好不好看、节奏对不对、包袱响不响，它一句不掺和——那是你的事。

行动件给你备好了。回去打开你自己的工程，跑一遍 check，看三样：红色的错误，照它递的修法改；黄色的警告，逐条读完再决定放行；退出码是零，再去按渲染。把它挂进你的出片流程，每次渲染前过一道——别用眼睛看，让机器先看；让错留在本地，别留到视频发出去以后。
