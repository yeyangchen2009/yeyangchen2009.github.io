【seg A · 好工程全绿｜操作：restore s0-good，终端跑 check】

哈喽大家好，我是叶扬。

上一集，我们终于让 div 动起来了：暂停的时间轴、seek 到任意一秒、帧帧可复现。可新问题来了——一个项目几百行 HTML、几十条动画，写完怎么知道自己没写错？靠眼睛从头看一遍？我先给你看个东西：有个错，就明晃晃写在标题颜色里，我自己盯着看了半天，没看出来。

今天的主角，是官方守门员：check。

先把丑话说前头，它不是万能的。上一集那个 setInterval 计数器，check 一路绿灯，可六台渲染器同时问第二秒，回来好几个不同的数——动画能不能被定位，这种运行时的逻辑，守门员不管。它管的是另一大类错：结构写错没、控制台炸没炸、布局遮没遮、字看不看得清。今天你会发现，光是这一类，就够救你好几回。

工程已经打开了，就一个标题、一个副标题，十秒。终端里敲：npx hyperframes@0.8.107 check，回车。注意，它不是一条检查，是六道关，一段段给你过：Lint，不起浏览器，纯读文件，查时间属性、查媒体文件在不在；Runtime，真开一个无头 Chrome 把页面跑起来，收控制台里的错和警告；Layout，在时间轴上抽九个点，一个个 seek 过去量布局；Motion，查动画写法——比如你写个无限循环，repeat 设成负一，它就黄你一下：视频是有终点的，末帧定格时循环停在哪，你想过没有；Contrast，每个采样点量文字和底色的对比度；最后 Snapshots，没配就是 disabled。全绿，Check passed。

【seg B · 删 duration｜操作：NPP 删 title 的 data-duration，存盘，check】

好，开始给它喂错。第一个，把标题身上的 data-duration 删掉。存盘，再 check。

一行黄字：timeline_element_missing_timing，说这个元素没有终点，时间轴画不出它在哪儿结束。可你抬头看——Check passed，绿灯。

这是今天第一个反直觉：这种错，它只警告，不拦你。为什么不拦？页面照样成立、照样能渲染；但后果是真的，它也写明了：海报帧、预览、最终渲染，这个元素都可能被切掉。所以黄字不是凑数的，是给人读的。

【seg C · 越界双修复｜操作：restore s2-overflow（tail 整块预置，跳切后镜头给代码），check；按建议现场改 root 10→13，复绿】

再来一个。片尾加个彩蛋，第八秒进来，待五秒。片子总长十秒，它得到第十三秒才走。check：clip_ends_past_root_duration，黄字。但这条警告有点东西，它直接递上两条修法：要么把根时长延到十三，要么让彩蛋在十秒前结束。我选第一条，root 的 data-duration 改成十三，再跑——绿了。

【论述卡① 警告与错误／退出码】

两类黄字看明白之后，规律就出来了：页面还成立、但有后果的，警告；页面不成立的，错误。再看退出码——有错是一，纯警告是零。所以这道闸能直接挂进 CI：退出码零才放行，黄字留给人逐条读。绿灯，从来不是免死金牌。

【seg D · 对比度主线｜操作：title color 改 #1a1f26，check（5✗ exit 1）；改 rgb(93,97,102) 复绿】

下面这个错，是让我决定拍这集的原因。

标题颜色我想弄高级点，挑了个深蓝灰，#1a1f26。说实话，在编辑器里我没觉得有大问题。check——Contrast 这一段，五个采样点全红：1.14 比 1，大字的门槛是 3 比 1。退出码一，真拦。

为什么大字反而只要 3 比 1，不是常见的 4.5？这是无障碍标准 WCAG 的口径：字越大、笔画越粗，容忍度越高。可我们这个标题，连三比一的三分之一都没到。

最狠的是它不光说你错了，还直接递上修好的颜色：试试 rgb(93,97,102)。抄上，复跑——十个检查点，全过。

那问题来了：这种错，Lint 为什么抓不着？因为「这个字在画面上到底清不清楚」，读文本是算不出来的。颜色叠上底色、透明度、动画走到一半的中间态，都得 Chrome 真把像素画出来才知道。这就是六道关为什么要分三层：静态读文件能查的，归 Lint；真跑起来才暴露的，归 Runtime；渲染出来才量得出的遮挡和对比，归 Layout 和 Contrast。人眼会累、会脑补，机器九个采样点，一个不落。

【seg E · 同轨重叠合法｜操作：restore s4-same-track，check 全绿；概念卡讲跨轨遮挡 text_occluded】

下一个实验，考的是成见。

两个片段，data-track-index 都写一，时间还重叠：第三秒到第七秒，标题跟副标题在同一根轨上叠着。按剪视频软件的直觉，同轨撞车，该报错了吧？check——全绿。

因为在渲染器眼里，压根没有「轨」这个东西。track-index 只是给官方 Studio 画轨道用的元数据；真正决定谁盖谁的，是 DOM 顺序，跟上一集讲层叠是同一个道理。

光说不练不过瘾，我在编辑器里把两个 div 的前后顺序对调一下，别的什么都不动，check——照样全绿。顺序怎么排，是你的设计，它不评判；它只在排序的后果真的闯了祸时才出手。

可你别以为它好糊弄：真弄个不透明色块压在文字上，它不管你写的是第几轨，Layout 采样点直接抓到 text_occluded——文字藏在不透明元素底下，错误。它查的从来是画面上的结果，不是你起的名字。

【seg F · GSAP 拼目标｜操作：restore s5-null-target（跳切后镜头先给 JS 区 #sut 拼写行，再跑 check）：3 warning 但 passed；概念卡补 page_error 连坐】

最后一种错，最阴。

给副标题补个淡入动画，选择器一顺手，井号 sub 拼成了井号 sut。check——passed，绿灯。但 Runtime 段里躺着三行警告：GSAP target #sut not found，还有两条连名字都空的。副标题的动画，就这么静悄悄地没了：不报错，不崩，不提醒你第二遍。

所以记住这个画面：绿灯不代表没事，黄字得逐条读完。那要是写错的不是选择器，而是真调了个不存在的函数？Runtime 直接 page_error，而且 Layout 连坐——时间轴压根没跑起来，它会明说：这一趟后面所有的绿，都不可信。

【seg G · 体检三连｜操作：restore s0-good 后依次 keyframes（列动画＋--shot 洋葱皮）、inspect（deprecated）、beats（无音乐提示）】

check 之外，还有三个体检命令，快速过一遍。

keyframes，把全片动画一条条列出来：哪个元素、从什么值到什么值、零点几几秒起步，比如标题这条，透明度从零到一、零到第一秒，清清楚楚；加个 shot 参数，还能出张洋葱皮图，首帧尾帧叠一块，动没动、动够没动，一眼破案。inspect 已经 deprecated 了，官方直接提示你改用 check；beats 查音乐轨的节拍，这片没音乐，它提示你给轨加个 data-timeline-role 等于 music。check 是出门前的安检，这三个，是体检报告。

【seg H · 收尾＋预告｜操作：终端定格 exit code】

收尾。check 把机器能判的都替你判了：结构、报错、遮挡、对比度；但片子好不好看、节奏对不对、包袱响不响，它一句不掺和——那是你的事。

行动件也给你备好了，回去打开你自己的工程，跑一遍 check，看三样：红色的错误，照它递的修法改；黄色的警告，逐条读完再决定放行；退出码是零，再去按渲染。把它挂进你的出片流程，每次渲染前过一道，让错留在本地，别留到视频发出去以后。
