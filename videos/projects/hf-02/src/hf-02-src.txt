上一集，我们认识了 HyperFrames——写一个网页，它给你渲染成视频。这一集，动手。

不过别急着写代码。做任何项目，头一件事都不是埋头就干，而是先把架子搭起来。HyperFrames 早就替你想到了：一条命令，三十秒，还你一个立刻能用的项目。

这条命令叫 init，initialize，初始化。后面空格，跟上你想起的项目名。我建一个，叫 demo，跑给你看。

你看，它几乎不问问题，噼里啪啦几下，一个完整的项目，就生成好了。

进去瞧瞧。文件不多，满打满算，六个。

但这六个文件，没一个是凑数的。我先带你挨个认个脸熟。

绝对的主角，是 index.html——你将来那条视频，说到底就是这一个网页。

围着它转的，还有五个。package.json，里头藏着四条快捷命令；meta.json，是这个项目的身份证，记着名字和出生时间；hyperframes.json，管工程配置，比如素材放哪儿、要不要自动代理。

最后这两个，CLAUDE.md 和 AGENTS.md，内容几乎一模一样。干什么用的？是写给 AI 编程助手看的说明书——这个项目里什么能做、什么不能做，规矩全写在里头。你让 AI 帮忙干活，它一进门，先读这个。

好，脸认完了。现在打开主角 index.html，真正的门道，在这儿。

不知道你平时做视频，时间是怎么安排的——在剪辑软件里，是拿鼠标把片段拖到时间轴的某一秒。可在 HyperFrames 这儿，时间不是拖出来的，是直接写在 HTML 标签上的。

你看最外层这个 div，id 叫 root。它就是整个项目的舞台，英文叫 stage。

舞台身上，挂着几个关键属性。data-composition-id，等于给这一整段合成起个名字，叫 main；data-width 和 data-height，声明画布有多大，1920 乘 1080；还有 data-duration，说这一整段，总共十秒。

舞台搭好了，里头上场的，才是一个个具体的片段，英文叫 clip。

你看这个 h1 标题，它带着 class 等于 clip，data-start 等于 0，data-duration 等于 10。翻译成人话就是：这个标题，从零秒开始上场，一直待到第十秒。

注意到没有——它什么时候出现、待多久，全是标签上的一个数字。这就是这个工具最不一样的地方：时间，是 DOM 的属性。

旁边还有一个，data-track-index 等于 0。这个管啥？管轨道。你可以把它想成舞台上的站位层数，数字大的，盖在数字小的上面；两个片段撞在一块儿，谁在前谁在后，就看它。

不过我得跟你说句实话：这个 track-index，主要是给那个可视化的编辑界面排位置用的；真到渲染的时候，程序压根不读它。所以这会儿，你只要知道「它代表轨道」，就够了。

那有人要问了：静态的位置和时间都有了，动画谁管？看最底下这一小段脚本。

它用 GSAP，建了一条 timeline，时间轴。你重点盯一个词——paused。这条时间轴刚建出来，是先暂停住的。

紧接着，它把这条暂停的时间轴，登记到 window.__timelines 这张表里。登记的名字，还是那个 main。

为什么非要「先暂停」，还得「登记」呢？因为这样一来，渲染器想知道第几秒的画面，根本不用从头播放，只要让这条时间轴直接 seek，跳到那一秒，画面立刻就位。

上一集我留了个扣子，说「跳到任意一帧」是它的灵魂。你现在大概能摸到一点边了。具体怎么做到的，第四集，我们专门讲。

好，index.html 看完，再回到 package.json。

它写好的四条命令，你连顺序都不用死记——npm run dev，启动预览；npm run check，自动检查；npm run render，渲染成片；npm run publish，发布出去。

你看，这四步，正好就是我们一直念叨的那条官方主流程。而且每一条，都把版本钉死在 0.8.107，跟整个系列一模一样，绝不偷偷给你升级。

光说不看也不行。我们跑头一条，npm run dev。

瞧见了吧，浏览器自动打开，这就是 init 给你的那个最小页面——深色底，中间一行标题，安安静静待在那儿。

别嫌它朴素。你现在看到的，已经是一条货真价实、十秒钟、随时能渲染成 MP4 的视频了。

所以你回头看 init 这三十秒——它不是给你扔一个空文件夹，让你抓瞎，而是把「舞台、片段、轨道、时间轴」这一整套规矩，连同一个真能跑起来的样板，一口气全给你立好了。

台子既然搭好，下一集，我们就往这个舞台上，摆头一个真正属于你自己的片段。
