标题三候选：
A 把每一帧看清楚：preview、snapshot 与逐帧验收
B 同一秒拍出四张不同的图：HyperFrames 帧验收实操
C 别信实时预览：把视频里任意一秒拍成照片

先做一个实验。

工程里两个方块，同一秒开始，沿着同一条路线，从左边滑到右边。蓝方块交给 GSAP，红方块交给 CSS 动画——就是写网页最常用的那套 keyframes。我开 preview，红的滑得又顺又稳，没有任何毛病。

然后我不拖进度条，让机器在同一秒钟连拍四张照片。命令是 snapshot，时点写四个一模一样的数字：第二秒、第二秒、第二秒、第二秒。

四张照片摆一块儿，蓝方块纹丝不动，像素级地稳；红方块呢，四张图，四个位置。

同一秒，同一个工程，连拍四次，给出四张不一样的画面。这要是拿去烤片，一帧零点几秒，上万帧烤一次大几十分钟，烤完才发现某个元素满屏乱飘，这大几十分钟就白等了。上集结尾留过一句话：声音画面都齐了，总不能闭着眼等渲染。今天就兑现——视频这东西，最怕的不是丑，是不确定。烤片之前，怎么把每一帧看清楚。

问题出在哪？出在两种动画，过的是两种时间。

浏览器里有个看不见的钟，从页面打开那刻起自己走，这个叫墙钟。CSS 动画听墙钟的：页面开了几秒，它就走到哪，你把进度条拖到第十秒，它不搭理——它只关心现实里过了几秒。所以连拍四个第二秒，四次拍照的瞬间墙钟走得不一样远，红方块就站在四个地方。我还试过把它改成只播一次、八秒播完、跟蓝块一样长，播完就停在终点，没用，第十秒拍出来它还停在起点附近。无限循环也好，一次播完也好，CSS 动画一律不听时间轴。

平心而论，这事赖不着 CSS。做网页的时候，页面本来就是打开给人看的，跟着墙钟走天经地义：loading 转圈、按钮 hover、弹窗淡入，全是这套。错的是把网页的习惯直接搬进视频——烤片不是在「播放页面」，是在「求每一帧的解」，同一个第几秒，不管求多少次，答案必须是同一个。

GSAP 那套老契约为什么管用？timeline 默认暂停，把每一个动作登记到 window 点 __timelines 那张表上，渲染器想烤第几帧，直接 seek 到第几帧，要哪帧给哪帧，帧帧确定。前面有一集说过，灵魂在 seek，这一集你看见反面教材了：不能 seek 的动画，实时预览里是活的，进了烤片炉就是薛定谔的猫。

那实时预览还要不要？要，它干它擅长的：听声音、看节奏、感受整片顺不顺。但「这一帧对不对」这个问题，永远别问实时预览，问 snapshot。

跟 check 分个工：check 是机器替你跑体检，结构非法、对比度不够、文件缺失，它按规则一条条查；可「这个东西此刻该不该在这个位置」「这个动作看着舒不舒服」，规则管不着，要靠你的眼睛看照片。机器全绿，只说明规矩没破，不说明画面是对的，两道闸谁也替不了谁。

snapshot 就是把任意一秒拍成照片。时点两种写法：你心里有数，用 at，把秒数一个一个列出来；只想均匀扫一遍，用 frames 给个数，它自己把整片等分，开头结尾自动带上。每张照片按秒数命名，额外还送一张接触表——所有时刻排在一张图上，等于给整片做了一次体检总览。想看清局部，zoom 后面跟一个选择器，或者直接给一块像素区域，它把那一块高密度裁出来；选择器写错了、啥也没选中，它不糊弄你一张全图，直接报错。

拍哪些秒，也有讲究。均匀拍五张是扫雷，真要放心，三个地方必须专门拍：每一段 clip 的接缝前后各一张，转场最容易穿帮；动作的中间状态拍一张，起步和落位往往都对，错在半途；还有你自己写得最心虚的那几句，单独点名。照片拍完不想要旧的也无妨，它只清理自己命名的帧，你搁旁边的别的文件，一律不碰。

有了照片，怎么判断一个动作本身对不对？总不能一格一格去对。keyframes 这条命令，加个 --shot 参数，能把一个元素在整条时间线上的轨迹拍成一张洋葱皮图：半透明的残影排在线上，第几秒在哪，拐弯没有，停顿没有，一眼看完。默认沿线采九个点，想密想疏用 samples 调，只关心某一段还能用 from、to 掐头去尾。它还能做体检：不加 --shot，光出报告——GSAP 动作、CSS 的 keyframes、Anime 的时间线，它都查得出来。

注意这个分寸：它查得出 CSS 动画的样子，从哪来到哪去写得清清楚楚，但查出来不等于驱得动。洋葱皮上 CSS 那块的残影，是照着声明推出来的几何示意，不是真烤出来的帧；真正的红方块在第几秒站哪，还是墙钟说了算。体检报告说「有这个东西」，跟时间轴说「我管得住它」，是两回事，别混。

再进一步，两个方案摆一块儿挑。做两张 HTML，一张方块走八百像素，一张走五百，颜色也换掉，compare 后面两个文件一摆，再给同一个秒数——一张对照图出来了，每格带编号带标签，同一个时刻两个方案并排站。不止两版也可以，它自己排版，一排最多四个。改布局、改配色、改动作幅度，不用来回切窗口，一张图投票。标签有个小脾气：它按逗号分段，标签里自己别写逗号，写了就被切成好几截。

两件小工具一句话带过。grade-compare 是拿同一帧套几种调色，暖色一档、高亮一档，摆一块儿选片用的，不是查帧用的；present 是把工程当幻灯片全屏放的演讲模式，也不是日常预览。


今天一集，记住三句话：实时预览管感受，snapshot 管事实，眼睛会骗人，帧不会；凡是要烤进片子的动画，必须能被 seek 管住，CSS 动画再好看，留给网页别留给视频；拿不准就拍照片——关键帧拍、接缝处拍、开头结尾拍，一张接触表胜过盯着播放头看半小时。

行动件：打开你手上的工程，先用 frames 拍五张，再找一个你最没把握的动作，keyframes 加 --shot 出一张洋葱皮。要是发现哪个元素只听墙钟的，趁早换回 seekable 的写法，别等整片烤完才认识它。

下一集，照片都验干净了，就该真烤了：无头浏览器怎样把网页一帧帧烤成 MP4，上万帧要烤多久，烤崩了怎么查。下一集，render。
