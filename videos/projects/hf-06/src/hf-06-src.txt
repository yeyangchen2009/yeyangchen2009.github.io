
前五集，我们做出来的片子，其实全是默片。

不信去翻工程：每一段录屏的 video 标签上，都写着同一个词——muted，静音。画面有了，动画有了，字幕有了，声音这一栏，空空荡荡。

今天这集，给片子配上声音。不光声音，图片、音乐、视频素材，怎么堂堂正正走进时间轴，一次讲完。

先说媒体三兄弟：图片 img、视频 video、音频 audio。

它们进时间轴的老契约不变：class 写 clip，data-start，data-duration——网页元素的时间，还是写在属性上，一行字都不用去时间轴上拖。

但媒体比普通的 div 多两条新规矩。第一条，就很要命：必须有 id。

不信你看。我把一段录屏视频的 id 删掉，别的什么都不动，跑 check——一条错误拍在脸上：这个视频有起始时间，却没有 id。渲染器是靠 id 把媒体登记进时间轴的；没有 id，它压根不知道这玩意儿存在。底下还有半句更狠：这个视频在渲染时会冻住，FROZEN。音频版同款：没有 id，渲染出来就是哑巴，SILENT。

记住这个差别：img 不写 id，只是个警告，Studio 不好点选而已；video 和 audio 不写 id，是硬错误。媒体要进场，先上身份证。

video 还得多回答一个问题：你这段素材，到底有没有声音？

录屏没开麦克风，是无声的——那就老老实实写 muted。素材自己带着声，你想保留——写 data-has-audio 等于 true。

不表态呢？error。它连一个默认值都不肯替你猜：有声没声明，渲染出来声画对不上，是你的事故；无声不声明，它也不替你背锅。

上集结尾，我埋了两个扣子，今天挨个兑现。

第一个扣子：文件找不到。

我把音频的 src 改坏一个字母，check——audio_src_not_found，音频引用了工程里不存在的文件，最后半句直接预告后果：渲染出来的视频，将会是静音的。

视频和图片版本的报错更损：渲染器会悄悄跳过它们——silently skip。你要是不跑 check，就会拿到一个缺胳膊少腿的片子，还以为一切正常。

这就是为什么要让机器先看：路径写错这种事，眼睛扫十遍都漏，机器一次就抓。check 的退出码是一，CI 那关，你过不去。

音频怎么进场？说个好玩的：你们听了九分钟的、我的这条声音，在工程里就是一个 audio 标签——id 叫 a-roll-audio，待在第二轨，data-volume 等于一。主角自己，也不过是个标签。

再加背景音乐，有个新讲究：别跟人声挤在同一条轨上。同一条轨道里，两段有声素材时间上叠着，它会警告你：这会造成层叠播放。两层声音糊成一团，谁也听不清。BGM 单独放第三轨。

放好了，再补一个属性：data-timeline-role 等于 music。眼熟吗？上集 beats 冲我甩过脸子：没找到音乐轨，给 audio 加个 data-timeline-role 等于 music。今天，音乐轨来了。beats 立刻有活干：它把整段音乐的拍子一个个标出来，写进 beats 文件夹。你想做卡点，这就是地图。

音量本身，三个小件。

data-volume：一，是原样；零，是静音；最大三点九八，等于硬加十二分贝。

data-fade-in 和 data-fade-out：片头音乐轻轻起来，片尾慢慢收掉，不砸耳朵。

一段素材只想用中间的一截？data-media-start，告诉它从素材的第几秒开始读；clip 有多长，就用多少，多出来的，不读。

现在，真正的问题来了：人声一轨，音乐一轨，谁响，谁轻？

凭耳朵拖滑块？你拖三遍，能给你三个数。早上拖和半夜拖，又不一样。

HyperFrames 给了一把客观尺：normalize-audio。它量的不是波形的高矮，是 LUFS，积分响度——耳朵真正感受到的那一种「这条音有多响」。

用法：指定一个参考轨，一个要调的目标轨。它两条都量，告诉你差距多少。我这片人声实测，负二十一点八 LUFS。

先空跑，只报数，不碰文件；加 --write，它才把算好的增益写回 data-volume。写完再跑第二遍——它说：已经齐了，在容差之内，不动。幂等的，你敢重复点。

但这把尺子，有脾气。

我故意把音乐压得很轻，再让它去追人声——一算，差了十六点零分贝。它直接拒绝：ok 是 false。理由是：超过正十二分贝的创作上限，这个差距，不该在混音台里补。

为什么？增益这东西，信号和噪声底是一起抬的。一条本来轻得离谱的素材，你硬加十六分贝，呼——底噪全起来了，音乐没响，沙沙声先响。它递了两条正路：回源文件去做响度归一化，比如 ffmpeg 的 loudnorm；或者，干脆把你的人声调小，让两边靠近。别在混音台上硬拗。

第二个扣子：媒体 id 对不上。上集我说，这在 lint 关是硬错误。真机一验，这话只对了一半，得拆成两种情况。

元素不写 id——硬错误，刚才演过了，冻帧、哑巴，一个都跑不掉。

可你要是在命令里把 id 写错呢？我让 normalize-audio 去配一个根本不存在的 id，bgn。它不客气：退出码是一，甩下一句英文——目标音频，没找到。但看清楚了，它只喊疼，不干活：工程文件一个字节没改，渲染压根没开始。这种红报错刷一下就滚出屏幕，你要是在脚本里不查退出码，连个响声都听不见。

想给画面调色，media-treatment 的选择器写错，同款待遇：一个元素都没匹配到，甩手就走。

看见没有——命令跑完，不等于活干完。报错甩在屏幕上，你没接住，跟它没喊，是一个下场。这跟上集那个井号 sut 是同一个鬼故事：你以为绿灯亮着，动画早就没了。每条命令，退出码要看，屏幕上的话要读，文件到底变没变，更要亲眼确认。

两件小事，快速带过。

远程素材：src 里直接写网址，它默认走自动代理，渲染时本地资源服务器替你把文件取回来；但你要是写个 example 点 com 那种占位网址，error 伺候——它分得清什么是真素材，什么是忘了填的坑。

图片和视频的画面本身，也能体检：media-treatment 加 analyze，抽几帧量曝光、量对比度，开一张调参的方子，apply 一下，确定性地写回工程。深色录屏普遍偏暗这种事，它一眼就量出来了。

收尾。

今天一集，记住三件事：素材进工程，id 是身份证，muted 是声音立场，文件必须真的在；多条音轨别叠一块儿，响度别靠猜，让 normalize-audio 拿 LUFS 量；屏幕上的每一句话都要读，退出码一个都别漏。

行动件给你备好了：打开你自己的工程，加一条音轨，配音也行，音乐也行；跑一遍 check，把红色错误清干净；再跑一遍 normalize-audio，亲眼看一眼，你的两条轨，差着多少个 LU。

下一集，声音和画面都齐了。可渲染一段要九分钟，全片烤一遍要六七十分钟，总不能闭着眼等。preview 实时看，snapshot 把任意一秒拍成照片，逐帧验收——下一集，把每一帧看清楚。

我是叶扬，我们下期见。
